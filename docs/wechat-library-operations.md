# 微信文库运行与维护手册

## 1. 安全边界

- 本手册只说明配置项和操作顺序，不保存任何真实密钥、证书内容、商户确认令牌或数据库口令。
- 禁止将 `.env`、`application.yml`、`application-druid.yml`、私钥、证书和微信开发者工具私有配置提交到 Git。
- 数据库初始化、发布、部署、支付和退款必须由获授权的运维人员在目标环境执行；开发验证不得连接生产商户或删除生产数据。
- 小程序使用独立的 `Wx-Token`，不得向 `/wx/**` 请求附带若依管理端 `Authorization`。

## 2. 运行环境

| 项目 | 要求 |
| --- | --- |
| Java | Java 8，本机验证路径为 `E:\JDK8\bin` |
| Maven | IntelliJ IDEA 2026.1.2 自带 Maven |
| Node.js | 18 或更高版本 |
| 数据库 | 与 RuoYi 3.9.2 兼容的 MySQL |
| 文档转换 | 受控的 LibreOffice/兼容转换程序，只允许配置的可执行文件 |
| 对象存储 | 腾讯云 COS 私有桶，禁止公共读 |
| 小程序 | 微信开发者工具与已备案 HTTPS 请求域名 |

## 3. 外部配置清单

以下值只能由运行环境注入，仓库不提供真实值。

| 前缀 | 配置项 | 用途 |
| --- | --- | --- |
| `wechat.login` | `app-id`、`secret`、`code2-session-url`、连接/读取超时 | 微信 `code2session` 登录 |
| `wechat.avatar` | `root-directory`、`max-bytes`、`max-width`、`max-height`、`max-pixels` | 本地头像隔离存储与图片限制 |
| `library.cos` | `region`、`bucket`、`secret-id`、`secret-key` | 私有文档和视频存储、短时签名 URL |
| `library.document-conversion` | `executable`、`temp-directory`、超时和输入/输出大小限制 | Office 转 PDF 与试读文件生成 |
| `wechat-library.pay` | `app-id`、`mch-id`、`api-v3-key`、商户证书序列号、私钥路径、支付/退款通知地址、退款确认令牌 | 微信支付、通知验签和全额退款 |

小程序发布前还需在 `miniprogram/app.js` 配置目标 HTTPS API 根地址和激励视频广告位编号。不得在该文件写入服务端密钥。

## 4. 初始化顺序

以下 SQL 仅供获授权人员评审后执行，本次代码交付未执行数据库迁移。

1. 先备份目标数据库并确认可恢复。
2. 按环境的 RuoYi 基础初始化流程准备基础表。
3. 评审并执行 `sql/wechat_library.sql`，确认所有微信文库表、唯一键、检查约束和审计字段存在。
4. 评审并执行 `sql/wechat_library_menu.sql`，为管理端创建菜单和权限标识。
5. 创建当前生效的“用户隐私协议”和“网站声明”，再开放小程序首次登录。
6. 配置积分规则、月卡/年卡、内容分类、私有 COS 桶和支付回调域名。

管理端文档录入顺序为：先保存公开元数据，再上传原文件并创建转换任务，转换成功后设置试读页数并发布。原文件、完整 PDF 和试读 PDF 的对象键只能由上传/转换服务维护，普通元数据编辑不得填写或覆盖。

## 5. 启动前检查

- 头像根目录与当月目录都必须是普通目录，不得是符号链接或目录联接；运行账户只授予所需读写权限。
- 文档转换临时目录必须独立、可清理、不可由外部请求直接访问；转换程序路径必须为明确的可信可执行文件。
- COS 桶必须保持私有，文档、原文件和视频只通过后端短时签名 URL 获取。
- 微信支付通知地址必须使用 HTTPS 且可由微信支付访问；支付和退款通知都必须经过官方 SDK 验签解密。
- `wechat-library.pay.refund-confirm-token` 使用独立高强度值，并通过安全渠道交付后台操作员。
- 管理端角色只授予实际需要的 `library:*` 权限；退款、权益补偿和课程码生成权限应单独控制。

## 7. 监控与审计

- 关注微信登录、令牌校验、协议更新、积分余额不足、文档转换失败、COS 签名失败、支付通知验签失败和退款通知异常。
- 不记录 `openid`、`session_key`、`Wx-Token`、APIv3 密钥、私钥内容、课程码明文或短时私有 URL。
- 使用积分流水、文档解锁记录、课程码使用记录、课程授权、视频进度、VIP 权益台账、支付订单、退款记录和管理员操作日志进行追踪。
- 支付回调允许重复投递；同一支付订单只能发放一次权益。退款只有收到最终成功通知后才撤销对应支付权益。
- 预支付订单先持久化稳定商户订单号，再调用微信支付；外部调用超时或预支付状态更新失败时保留订单用于按商户订单号对账，不得生成新订单规避歧义。
- 退款积分不足时余额最低为零，并保留“未追回积分”审计值，不得通过手工改余额隐藏差额。

## 8. 故障处理

| 场景 | 处理方式 |
| --- | --- |
| 微信登录失败 | 检查外部配置、微信接口连通性和安全日志，不打印 `code` 换取结果中的敏感字段 |
| 头像写入失败 | 检查目录权限、符号链接防护、图片格式/像素限制；事务回滚后确认新文件已补偿删除 |
| 文档转换失败 | 检查任务错误摘要、进程超时和临时空间；修复后通过管理端重试，不直接公开源文件 |
| 支付显示确认中 | 按商户订单号查询后台状态；不得由客户端本地补发会员 |
| 重复支付通知 | 核对订单和权益台账，确认幂等；不要手工重复发放 |
| 退款受理中 | 等待最终退款通知，不提前撤销会员权益 |
| 用户被停用 | 现有 `Wx-Token` 应立即被拦截且 TTL 不刷新；排查时不得临时绕过拦截器 |

## 9. 备份、回滚与恢复

- 发布前备份数据库和当前应用包，记录 SQL 版本与 Git 提交号。
- 应用回滚不能擅自回滚已经确认的支付、退款、积分或权益事实；先停止写流量，再依据台账制定补偿方案。
- COS 与头像文件的清理必须依据数据库状态和保留策略执行，不允许使用宽泛递归删除命令。
- 恢复后重新核对支付订单、退款记录、VIP 权益、积分流水、文档授权和课程授权的一致性。
