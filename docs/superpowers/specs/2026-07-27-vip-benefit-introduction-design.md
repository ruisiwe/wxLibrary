# VIP 权益介绍设计

## 目标

在微信小程序 VIP 套餐页面的套餐列表下方增加全局共用的 VIP 权益文字介绍和客服微信图片。权益文字、客服微信图片及提示语均可在若依后台的“VIP 权益介绍”页面维护。

本功能不改变现有 VIP 套餐、支付、兑换码、会员有效期、赠送积分和 `VIP_FREE` 文档访问逻辑。

## 展示规则

### 小程序 VIP 套餐页面

页面按以下顺序展示：

1. 当前会员状态。
2. VIP 套餐列表及现有购买、续费入口。
3. “VIP 权益”区域，展示全部已启用的权益文字，按排序值和记录编号升序排列。
4. 客服微信区域，展示客服微信图片和提示语。

初始权益包括：

- 赠送积分
- VIP 文档免费下载
- VIP 专属课件

默认客服提示语为“开通 VIP 请添加客服微信”。

权益介绍为所有 VIP 套餐共用的纯文字列表，不为月卡、年卡分别配置。权益没有图标、富文本或跳转链接。

客服微信图片未配置时，隐藏整个客服微信区域，不显示空白占位或破图。权益配置请求失败时，显示简体中文重试提示，但已成功加载的套餐和会员信息仍正常展示。

## 后台维护页面

在后台“会员管理”菜单下新增“VIP 权益介绍”页面，页面包含两个区域。

### 客服配置

- 上传或替换客服微信图片。
- 编辑客服提示语。
- 图片支持 JPEG、PNG、WebP，最大 2 MB。
- 展示当前图片预览。
- 保存新图片成功后再清理旧图片，避免保存失败导致原图片丢失。
- 客服提示语必填，去除首尾空格后长度为 1 至 100 个字符。

### 权益列表

- 新增、修改、删除权益。
- 维护权益文字、排序和启用状态。
- 权益文字必填，去除首尾空格后长度为 1 至 100 个字符。
- 排序必须是非负整数。
- 状态使用现有约定：`0` 为启用，`1` 为停用。

## 数据模型

### `wl_vip_benefit`

每条记录代表一条全局 VIP 权益文字，主要字段为：

- `id`：主键。
- `benefit_text`：权益文字。
- `sort_order`：排序值。
- `status`：启用状态。
- 若依通用审计字段：`create_by`、`create_time`、`update_by`、`update_time`、`del_flag`、`remark`。

### `wl_vip_page_config`

使用单例记录保存 VIP 页面客服配置，固定主键为 `1`，主要字段为：

- `id`：固定为 `1`。
- `customer_service_image_key`：私有对象存储中的客服微信图片键。
- `customer_service_tip`：客服提示语。
- 若依通用审计字段：`create_by`、`create_time`、`update_by`、`update_time`。

数据库变更写入 `docs/2026-07-27-vip-benefit-introduction.sql`，不执行数据库迁移或发布。为保证全新环境可初始化，同时同步维护基础建表脚本和菜单脚本。

## 后端边界

新增独立的领域对象、Mapper 和 Service，避免把全局页面配置混入 `WlVipPlan`。

后台接口使用 `/library/vip-benefit` 维护权益列表，使用 `/library/vip-page-config` 查询和保存客服配置、上传客服图片。接口写简体中文注释，校验错误和请求错误均返回简体中文。

小程序新增 `/wx/vip/page-config` 查询接口，返回：

- 已启用且排序后的权益文字列表。
- 客服提示语。
- 客服图片短时访问地址；未配置图片时为空。

现有 `/wx/vip/plans` 套餐接口和支付接口保持不变。

客服微信图片使用现有私有对象存储能力，采用独立的图片校验与存储服务，不复用轮播图的固定尺寸裁剪规则。后台预览和小程序展示均获取短时访问地址，不返回永久公开地址。

## 前端边界

### 若依后台

新增独立 Vue 页面和 API 模块：

- 客服配置使用上传控件、图片预览、提示语输入框和保存按钮。
- 权益列表使用表格和新增、修改、删除操作。
- 菜单名称、页面标题和操作日志名称统一使用“VIP 权益介绍”。

### 微信小程序

扩展 VIP service，新增页面配置请求。VIP 套餐页面分别维护套餐、会员信息和页面配置的加载状态，避免页面配置失败清空已加载的套餐。

页面使用纯文字权益列表。客服微信图片保持原比例展示，提示语显示在图片下方。

## 权限和菜单

在“会员管理”下新增“VIP 权益介绍”菜单，并增加以下权限：

- `library:vip:benefit:list`
- `library:vip:benefit:add`
- `library:vip:benefit:edit`
- `library:vip:benefit:remove`
- `library:vip:page-config:query`
- `library:vip:page-config:edit`

菜单和按钮权限 SQL 纳入独立数据库变更脚本及基础菜单脚本。

## 错误处理

- 后台校验失败返回明确的简体中文原因。
- 图片格式不支持、图片超过 2 MB、图片无法解码或上传失败时，不更新数据库配置。
- 数据库保存失败时清理本次新上传的图片并保留旧配置。
- 替换成功后清理旧图片；旧图片清理失败不回滚已经成功的新配置，但记录错误日志。
- 小程序页面配置加载失败时提供重试入口，不阻断套餐购买流程。

## 测试与验证

后端测试覆盖：

- 权益文字、排序和状态校验。
- 仅返回已启用权益，并按排序值和记录编号排序。
- 客服提示语校验。
- 图片格式、大小和解码校验。
- 图片替换成功、保存失败回滚及旧图清理边界。
- 后台及小程序控制器响应契约。
- MyBatis 映射和 SQL 建表契约。

小程序测试覆盖：

- 权益文字按接口结果展示。
- 客服图片和提示语展示。
- 未配置客服图片时隐藏客服区域。
- 页面配置加载失败不影响套餐及会员信息。
- 重试能够单独重新加载页面配置。

后台前端测试覆盖：

- 页面标题和字段。
- 权益 CRUD API。
- 客服图片 multipart 上传及配置保存请求。
- 菜单与权限契约。

完成后使用 Java 8 和 IntelliJ 自带 Maven 运行相关后端测试，并运行小程序及后台前端的针对性测试。根据验证范围决定是否补充完整模块测试或构建，不执行发布、部署或数据库迁移。

## 不在本次范围

- 不调整 VIP 套餐价格、有效期或赠送积分数值。
- 不改变微信支付、退款、VIP 兑换码和会员续期逻辑。
- 不改变 `VIP_FREE` 文档的授权和解锁逻辑。
- 不提供富文本权益、权益图标、权益跳转或按套餐区分的权益。
- 不提供客服微信号复制、扫码识别或微信原生客服会话能力。
