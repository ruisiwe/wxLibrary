# 文档列表展示、免费直达与首页静默登录设计

## 目标

修复“我的文档”缩略图返回相对对象键导致无法显示的问题，在首页文档标题前增加文件类型标签，让有效会员的会员文档和所有 0 积分文档无需手动兑换即可发送原文件，并在首页为已注册用户执行一次静默登录。

## 范围

- 小程序“我的文档”缩略图地址。
- 小程序首页文档列表的文件类型标签。
- 小程序文档详情页的免费直达按钮与自动解锁流程。
- 小程序首页首次进入时的登录状态检测。
- 后端缩略图签名和仅免费解锁能力。

本次不调整数据库结构，不修改文档原文件授权、免责声明、COS 短时签名或微信文件发送的既有流程，不改变非会员购买非 0 积分文档时的积分兑换规则。

## 根因

公开首页、搜索和文档详情由 `HomeQueryService` 查询文档后，将相对 `coverUrl` 通过 `PrivateFileUrlSigner` 转换为完整签名 URL。“我的文档”由 `DocumentAccessService.listUnlocked()` 直接返回 `WlDocumentUnlockMapper` 查询结果，没有执行同一签名步骤，因此响应中保留了 `documents/.../thumbnail/v1.jpg` 形式的私有对象键。

首页文档行目前直接显示标题，没有文件类型标签。文档详情页仅以是否存在兑换记录决定展示“积分兑换”或“发送原文件”，无法表达“当前请求可以免费建立兑换记录”的状态。首页也只加载匿名内容，没有主动调用已有的静默登录能力。

## 方案

### 共享缩略图签名

从 `HomeQueryService` 中提取文档缩略图签名逻辑为共享的 `DocumentCoverUrlService`。首页、搜索、文档详情以及“我的文档”复用该服务，而不是让“我的文档”再次请求首页 HTTP 接口。

共享服务遵循以下规则：

- 空地址保持为空。
- 已以 `http://` 或 `https://` 开头的完整地址保持不变。
- 其他地址按私有对象键处理，生成 30 分钟有效的完整签名 URL。
- 签名器不可用、返回空地址或签名异常时，统一抛出“缩略图服务暂不可用，请稍后重试”。

`DocumentAccessService.listUnlocked()` 查询完成后调用共享服务处理列表，再返回给“我的文档”页面。收藏列表不在本次需求范围内，不改变其现有行为。

### 首页文件类型标签

共享 `document-row` 组件增加一个默认关闭的布尔属性 `showFileType`，首页使用组件时显式开启。其他复用页面不会因本次需求自动出现标签。

开启后，在标题前同行展示文件类型：

- 文案来源为 `document.fileFormat`，统一转为大写英文，例如 `PDF`、`PPTX`。
- 标签为红色背景、白色文字和圆角样式。
- 标签与标题垂直居中，标题仍保持溢出约束，长标题不会挤破文档行布局。
- 文件类型为空时不显示标签。

### 免费直达与仅免费解锁

详情页计算 `canSendOriginal` 状态：

- 已兑换文档为真。
- `pointPrice` 为 0 的文档为真。
- 文档 `accessType` 为 `VIP_FREE` 且当前用户会员仍有效时为真。
- 其他情况为假。

`canSendOriginal` 为真时显示现有“发送原文件”按钮；为假时显示现有“积分兑换”按钮。有效会员判断继续使用会员资料接口的 `vipActive` 字段。

当用户点击“发送原文件”且尚无兑换记录时，小程序先调用文档兑换接口建立 0 积分兑换记录，成功后继续现有免责声明、原文件授权、下载和微信发送流程。该自动调用携带“仅允许免费解锁”标记，避免会员状态在页面加载后失效时被静默扣除积分。

后端兑换逻辑增加以下约束：

- 0 积分文档直接建立 `spentPoints = 0` 的兑换记录，不产生积分扣减记录。
- 有效会员兑换 `VIP_FREE` 文档时直接建立 `spentPoints = 0` 的兑换记录。
- “仅允许免费解锁”请求若在服务端判断需要扣积分，则拒绝请求且不扣积分，返回简体中文错误提示。
- 普通积分兑换请求保持现有扣积分、幂等请求编号和价格快照行为。
- 原文件授权仍要求兑换记录存在，不放宽安全边界。

### 首页静默登录

首页 `onLoad` 同时启动匿名首页数据加载和一次登录状态检测，两者互不阻塞：

- 本地已有令牌时直接使用，不再次请求登录。
- 本地没有令牌时调用已有 `auth.silentLogin()`。
- 已注册微信用户由后端识别并保存新令牌及用户资料，全程不弹窗。
- 首次用户需要头像资料或静默登录发生网络错误时，首页保持匿名可用，不展示登录弹窗或错误提示；用户执行受保护操作时仍沿用现有登录引导。
- 登录检测仅由首页本次 `onLoad` 触发一次，`onShow` 不重复调用。

## 数据与接口变化

`DocumentUnlockRequest` 增加可选布尔字段 `freeOnly`，表示“仅允许免费解锁”。字段缺省或为 `false` 时按现有普通兑换处理，保证已有调用兼容。小程序文档服务在自动解锁场景传入 `freeOnly: true`，用户确认积分兑换时不传该字段。

不新增数据库表或字段，不执行数据库迁移。

## 错误处理

- 缩略图无法签名时返回“缩略图服务暂不可用，请稍后重试”。
- 仅免费解锁条件已失效时返回“当前文档不再满足免费获取条件，请刷新后重试”，且不创建兑换记录、不扣积分。
- 首页静默登录错误不覆盖首页内容加载状态。
- 自动解锁失败时停止免责声明和文件发送流程，并使用后端简体中文错误提示。
- 文件免责声明、短时授权、下载和发送错误继续使用现有处理。

## 测试

后端单元测试覆盖：

- 共享缩略图服务把相对对象键转换为 30 分钟签名 URL。
- 共享缩略图服务保持空地址和完整 HTTP/HTTPS 地址不变。
- `HomeQueryService` 和 `DocumentAccessService.listUnlocked()` 均使用共享签名服务。
- 0 积分文档建立 0 积分兑换记录且不调用积分扣减。
- 有效会员免费解锁会员文档。
- 仅免费解锁请求在需要扣积分时拒绝且不调用积分扣减。
- 普通非会员积分兑换保持原行为。

小程序测试覆盖：

- 首页启用文件类型标签，其他页面默认不启用。
- 类型标签位于标题前，使用大写文件类型、红底白字和圆角样式。
- 已兑换、有效会员的会员文档、0 积分文档显示“发送原文件”。
- 免费但未兑换的文档先发起仅免费解锁，再继续发送流程。
- 非会员的非 0 积分文档继续显示“积分兑换”。
- 首页无令牌时仅调用一次静默登录，有令牌时不重复登录。
- 首页静默登录失败不弹登录窗口且不阻塞匿名首页数据。

验证时使用 `E:\JDK8\bin` 和 IntelliJ 自带 Maven 运行相关 Java 测试，并使用项目可用的现代 Node.js 运行小程序契约测试。最后执行 `git diff --check`，确认没有空白错误，也不读取或修改敏感配置文件。
