# 轮播图本地选择、裁剪与 COS 上传设计

## 1. 目标

管理端轮播图不再手工填写图片地址。管理员从浏览器选择本地 JPG 或 PNG 图片，在管理端裁剪为固定 `1240×480` 像素后，与轮播图元数据一起提交。后端验证图片真实性、大小和精确尺寸，将图片上传到现有私有 `file-1302202133` COS 桶，并在 `wl_banner.image_url` 中保存对象键。

小程序现有轮播区域为 `620rpx×240rpx`，比例为 `31:12`。裁剪框和最终图片都锁定为该比例，避免小程序使用 `aspectFill` 时二次截断。

## 2. 范围

本次包括：

- 管理端浏览器选择图片、固定比例裁剪、缩放、移动、旋转、预览和重新选择。
- 新增和修改轮播图的 multipart 保存接口。
- 后端图片真实性、大小、格式、像素和精确宽高校验。
- 私有 COS 上传、短时预览地址、事务补偿和旧图清理。
- 删除轮播图后清理对应 COS 图片。
- 管理端和小程序的图片地址适配。
- Controller MockMvc、服务单元测试和前端源代码测试。

本次不包括：

- 不允许继续填写任意图片 URL。
- 不使用 Base64 保存数据库。
- 不增加轮播图数据库字段或新建表。
- 不让浏览器直接上传 COS。
- 不连接真实 COS、不部署、不执行数据库迁移。

## 3. 管理端交互

轮播图页面保留标题、关联文档、排序、状态和起止时间字段，移除“图片地址”文本输入框。

图片字段使用 Element UI `el-upload` 选择本地文件，并复用项目已有 `vue-cropper`：

1. 仅允许 JPG、JPEG、PNG，浏览器选择文件上限为 5MB。
2. 选择后打开裁剪弹窗，裁剪比例固定为 `31:12`，不能自由修改比例。
3. 支持移动图片、放大、缩小、向左旋转、向右旋转和重新选择。
4. 点击“确认裁剪”后，通过浏览器 Canvas 输出精确 `1240×480` JPEG Blob，并显示预览。
5. 新增轮播图必须完成裁剪；没有裁剪结果不能保存。
6. 修改轮播图时显示当前短时预览图。管理员不选择新图片时保留原对象键；完成新裁剪时替换原图。
7. 图片或元数据正在保存时禁止重复提交和关闭裁剪窗口。
8. 上传失败保留裁剪结果和表单内容，允许直接重试。

轮播图页面可从通用 `SimpleList` 中拆为专用页面，避免给所有简单维护页加入仅轮播图需要的 multipart 和裁剪状态。

## 4. 接口设计

保留列表、关联文档搜索和删除接口；新增、修改改为 multipart。

### 4.1 新增

```http
POST /library/banner
Content-Type: multipart/form-data
```

请求包含：

- `banner`：`application/json`，包含标题、关联文档、排序、状态、开始时间和结束时间，不接受客户端图片地址。
- `image`：裁剪后的 JPEG 文件，必填。

权限仍为 `library:banner:add`。

### 4.2 修改

```http
PUT /library/banner
Content-Type: multipart/form-data
```

- `banner`：`application/json`，包含轮播图编号和可修改元数据。
- `image`：可选。未上传时保留旧图；上传时替换旧图。

权限仍为 `library:banner:edit`。

### 4.3 管理端预览

```http
GET /library/banner/{id}/image
```

后端校验 `library:banner:list` 或编辑权限后，为数据库中的对象键签发短时 GET 地址并返回。管理端不能把该短时地址写回数据库。

### 4.4 删除

现有删除接口保持不变。数据库软删除成功提交后，再删除对应 COS 对象；COS 清理失败只记录安全日志，不回滚已完成的数据库删除。

## 5. 后端图片处理

后端不信任浏览器提供的文件名、MIME 或宽高，必须重新验证：

- 文件非空且不超过 5MB。
- 文件名扩展名仅允许 `.jpg`、`.jpeg`。
- multipart MIME 必须为 `image/jpeg`。
- 使用 `ImageReader` 先读取格式和宽高元数据，再解码图片。
- 实际格式必须为 JPEG。
- 宽高必须精确为 `1240×480`，总像素不得超过服务硬限制。
- 解码成功后重新编码为 JPEG，去除不需要的原始元数据。

PNG 只作为浏览器选择和裁剪输入；浏览器确认裁剪后统一提交 JPEG。因此后端最终上传接口只接收 JPEG。

临时文件放入文档转换配置所指向的受控根目录下的独立轮播会话目录。根目录、会话目录和文件都拒绝符号链接；临时文件在请求完成后清理。

## 6. COS 对象与事务

对象键格式：

```text
banners/{UUID}/image.jpg
```

数据库继续使用 `wl_banner.image_url` 保存对象键，不保存签名 URL。

### 新增

1. 校验元数据和图片。
2. 上传新 COS 对象。
3. 在数据库事务中新增轮播图。
4. 数据库失败或回滚时删除新对象。
5. 提交成功后返回轮播图编号。

### 修改

1. 查询并锁定当前轮播图的旧对象键语义。
2. 没有新图片时只修改元数据并保留旧对象键。
3. 有新图片时先上传新对象，再使用旧对象键作为并发条件更新数据库。
4. 数据库失败或并发冲突时删除新对象，保留旧对象。
5. 数据库提交成功后删除旧对象。

### 删除

1. 先读取待删除记录及对象键。
2. 在数据库事务中完成软删除。
3. 提交成功后删除 COS 对象。

任何补偿失败都只记录对象键，不记录 COS 密钥、签名 URL 或云端异常详情。

## 7. 小程序读取

首页查询得到轮播图对象键后，由 `HomeQueryService` 使用现有私有文件签名能力转换为短时 GET 地址。已有 HTTP/HTTPS 历史地址在过渡期只读兼容，但管理端新增和修改不再接受外部 URL。

小程序展示尺寸和点击关联文档逻辑保持不变。COS 域名继续加入小程序 `downloadFile` 合法域名。

## 8. 错误处理

接口注释、请求返回和错误信息使用简体中文，不使用 Unicode 转义。对外错误包括：

- “请选择轮播图片”
- “轮播图片不能超过5MB”
- “轮播图片格式不支持”
- “轮播图片扩展名、MIME类型与实际格式不一致”
- “轮播图片尺寸必须为1240×480像素”
- “轮播图片处理失败，请重试”
- “轮播图片保存失败，请重试”
- “轮播图已被修改，请刷新后重试”

未知异常由现有管理端异常处理边界转换为安全响应，不向前端暴露服务器路径或 COS 细节。

## 9. 测试

后端测试：

- 真实 Controller MockMvc 覆盖 multipart 新增、修改、可选图片和错误媒体类型。
- 服务测试覆盖超过 5MB、伪造扩展名/MIME、非 JPEG、错误宽高和有效 `1240×480` JPEG。
- 覆盖新增数据库失败删除新对象。
- 覆盖修改失败删除新对象且保留旧对象。
- 覆盖修改成功提交后删除旧对象。
- 覆盖删除成功后清理图片以及数据库失败时不删除图片。
- 覆盖管理端预览签名和小程序首页短时签名。

前端测试：

- 页面不再出现“图片地址”输入框。
- 使用 `el-upload` 和 `vue-cropper`。
- 裁剪比例锁定 `31:12`，最终 Canvas 为 `1240×480`。
- 新增无裁剪结果不能提交。
- 修改无新图保留旧图，裁剪新图后使用 multipart 替换。
- 保存失败保留裁剪预览并允许重试。

验证使用 Java 8、IntelliJ 自带 Maven、小程序 Node 测试和管理端生产构建。测试不得连接真实 COS。

## 10. 数据库与配置影响

不修改 `wl_banner` 表结构，不新增 SQL。继续复用：

- `wl_banner.image_url` 保存 COS 对象键。
- `library.cos` 使用现有 `file-1302202133` 私有桶。
- `library.document-conversion.temp-directory` 下建立隔离的轮播图临时目录。

如果部署环境希望把轮播图片临时目录与文档目录完全隔离，可在后续单独增加配置；本次不增加不必要的配置项。
