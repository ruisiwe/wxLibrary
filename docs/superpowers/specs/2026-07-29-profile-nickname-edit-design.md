# 小程序“我的”页面修改昵称设计

## 目标

在小程序“我的”页面用户信息卡片的昵称右侧增加“编辑图标 + 修改昵称”小按钮。用户点击后通过微信原生输入弹窗修改昵称，并立即刷新页面显示。

## 页面布局

- 按钮放在昵称右侧，与昵称处于同一行。
- 使用现有 TDesign MiniProgram 的 `edit-1` 图标，不新增图片或图标依赖。
- 按钮文字为“修改昵称”，使用小字号。
- 图标、文字使用半透明白色，适配当前深蓝色用户卡片。
- 昵称区域允许收缩和省略，避免较长昵称挤出卡片。
- 按钮保持固定可见，不被长昵称压缩。

## 交互流程

1. 用户点击“修改昵称”。
2. 调用微信原生 `wx.showModal`，设置 `editable: true`，默认带出当前昵称。
3. 用户取消时不执行任何请求。
4. 用户确认后对输入内容执行首尾空格清理。
5. 输入为空时提示“昵称不能为空”，不发送请求。
6. 输入与当前昵称相同时直接关闭，不发送请求。
7. 保存期间使用页面状态阻止重复提交。
8. 调用现有 `auth.updateNickname`，请求 `PUT /wx/profile`。
9. 保存成功后：
   - 使用接口返回资料更新页面中的 `profile`。
   - 同步 `session` 中当前用户的昵称，避免其他页面读取旧昵称。
   - 提示“昵称修改成功”。
10. 保存失败时显示后端返回的简体中文错误；没有明确错误信息时显示“昵称修改失败，请稍后重试”。

  - 增加昵称行容器及“修改昵称”按钮。
- `miniprogram/pages/profile/profile.wxss`
  - 增加昵称行、昵称省略和按钮样式。
- `miniprogram/pages/profile/profile.js`
  - 增加弹窗、校验、提交、页面刷新和会话同步逻辑。
- `miniprogram/tests/profile-nickname-edit.test.js`
  - 增加页面结构与交互契约测试。

## 复用与兼容性

- 复用现有 `miniprogram/services/auth.js` 中的 `updateNickname` 方法。
- 复用现有后端昵称长度、HTML 标签和控制字符校验。
- 不修改登录流程、随机昵称生成规则或头像。
- 不修改数据库、后端接口和鉴权方式。
- 保留工作区中其他既有未提交改动。

## 测试

- 验证 `profile.json` 注册 `t-icon`。
- 验证昵称右侧包含 `edit-1` 图标和“修改昵称”文字。
- 验证按钮绑定昵称编辑事件。
- 验证弹窗启用 `editable: true` 并带出当前昵称。
- 验证取消、空昵称、相同昵称不会调用更新接口。
- 验证保存期间阻止重复提交。
- 验证成功后更新页面资料和本地会话，并显示成功提示。
- 验证失败时显示接口错误。
- 运行小程序现有 Node 测试套件。
