# 我的文档本地搜索与列表类型标签设计

## 目标

在“我的文档”和分类文档列表中显示与首页一致的文件类型前缀，并为“我的文档”增加不请求后台的实时标题搜索。

## 范围

- “我的文档”列表显示大写文件类型标签。
- 分类详情中的文档列表显示大写文件类型标签。
- “我的文档”顶部增加实时搜索输入框。

本次不修改搜索结果页，不增加后端接口，不改变“我的文档”已有数据来源、排序或跳转行为。

## 类型标签

首页已经通过共享 `document-row` 组件的 `showFileType` 属性显示红底白字、圆角的大写文件类型。此次不复制标签结构或样式，只在以下页面调用组件时显式传入 `show-file-type="{{true}}"`：

- `pages/my-documents/my-documents.wxml`
- `pages/category/category.wxml`

文件类型为空时继续由共享组件隐藏标签。

## 本地实时搜索

“我的文档”页面维护三项状态：

- `allItems`：接口本次返回的完整已兑换文档数组。
- `items`：当前实际渲染的文档数组。
- `searchKeyword`：搜索框当前值。

页面首次加载或重试成功后，同时更新 `allItems` 和 `items`。输入框触发 `bindinput` 时，对 `allItems` 实时过滤并写入 `items`，不调用 `documents.unlocked()` 或其他后台接口。

过滤规则如下：

- 仅匹配文档 `title`。
- 去除关键词首尾空格。
- 使用不区分大小写的包含匹配。
- 标题为空时按空字符串处理。
- 关键词为空时恢复完整列表。
- 保持原数组顺序，不做额外排序。

## 页面状态

搜索输入框位于列表上方，使用圆角浅灰背景，不配置单独的搜索按钮，输入即生效。

- 接口返回的完整列表为空时显示“还没有兑换文档”。
- 完整列表非空但搜索结果为空时显示“未找到相关文档”。
- 加载或接口错误状态继续沿用现有 `state-view` 和重试逻辑。
- 接口重试成功后，使用当前 `searchKeyword` 重新过滤最新数据，避免搜索条件被清空。

## 实现边界

标题过滤实现为文档服务模块中的纯函数 `filterDocumentsByTitle(items, keyword)`，页面只负责保存状态和响应输入事件。纯函数可直接通过 Node.js 测试验证，不依赖微信运行环境。

## 测试

小程序测试覆盖：

- 过滤函数支持不区分大小写的标题包含匹配。
- 关键词首尾空格被忽略，空关键词恢复全部数据。
- 空标题安全处理，过滤保持原顺序且不修改原数组。
- “我的文档”输入事件只调用本地过滤函数，不再次请求后台。
- “我的文档”和分类列表均显式开启共享文件类型标签。
- 搜索无结果和原始空列表显示不同的简体中文空状态提示。

验证使用项目可用的现代 Node.js 运行相关测试，并执行 `git diff --check`。不读取或修改 `.env`、`application.yml`、`application-druid.yml`，不提交构建产物。
