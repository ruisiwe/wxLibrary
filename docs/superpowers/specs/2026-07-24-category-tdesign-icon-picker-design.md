# 分类 TDesign 图标选择设计

## 1. 状态

- 设计日期：2026-07-24
- 设计状态：已确认
- 适用范围：后台文档分类管理、小程序首页分类宫格

## 2. 背景

`wl_category` 已有 `icon` 字段，后台分类管理目前把它作为普通“图标地址”文本输入。小程序分类接口已经返回 `icon`，但分类宫格仍通过 `item.iconUrl` 使用 `<image>` 渲染，字段和展示方式不一致。

小程序固定使用 `tdesign-miniprogram 1.15.3`。分类图标应保存为 TDesign 图标名称，例如 `time`，小程序通过 `<t-icon name="{{item.icon}}" />` 渲染对应的时钟图标。后台管理人员不能手工记忆图标名称，需要在管理页面看到图标预览并点击选择。

## 3. 目标

1. 后台展示一组业务精选 TDesign 图标，支持按中文名称、图标名称和关键词搜索。
2. 后台图标预览与小程序使用同一个 `name`，例如两端都使用 `time`。
3. 数据库只保存图标名称字符串，不保存图片地址、SVG 内容或组件代码。
4. 后端统一维护可选目录并校验提交值，阻止错误或任意图标名称写入。
5. 保持现有分类表和公开分类接口字段不变。

## 4. 非目标

- 不开放全部约 2350 个 TDesign 图标。
- 不允许管理员上传分类图标图片。
- 不新增图标数据库表。
- 不允许管理员自由输入未收录的图标名称。
- 不改动其他业务页面的图标体系。

## 5. 方案选择

### 5.1 采用方案

管理端安装并锁定 Vue 2 版本的 `tdesign-icons-vue`，使用通用 `Icon` 组件按名称渲染预览。后端提供业务精选图标目录，管理端遍历目录，选中后只提交 `name`。

小程序继续使用 `tdesign-miniprogram` 的 `<t-icon>`。两端约定相同的名称字符串，数据库和接口不感知具体图形。

### 5.2 未采用方案

1. **复用小程序 `icon.wxss`**：显示效果最接近小程序，但管理端会依赖小程序编译产物和远程字体，模块边界和升级流程不清晰。
2. **维护 SVG 或 PNG 预览图片**：实现直观，但每个图标要同时维护预览资源和 TDesign 名称，容易产生重复和不一致。
3. **在数据库维护图标目录**：引入了没有业务必要的表、管理功能和迁移成本，且图标集合实际受前端依赖版本约束。

## 6. 精选图标目录

后端新增不可变的分类图标目录。每项包含：

```json
{
  "name": "time",
  "label": "时间",
  "keywords": "时间 时钟 日期"
}
```

| name | 中文名称 |

## 7. 后端设计

### 7.1 图标目录

在 `ruoyi-wechat-library` 中增加独立的分类图标目录组件，负责：

- 返回按产品定义排序的图标选项。
- 根据 `name` 查询选项。
- 判断名称是否有效。
- 提供缺省名称 `file`。

目录不依赖控制器和数据库，便于服务层校验和单元测试。

### 7.2 管理接口

在现有 `LibraryCategoryController` 下增加：

```http
GET /library/category/icon-options
```

权限使用：

```text
library:category:list
```

接口返回 `name`、`label` 和 `keywords`。接口注释、失败信息使用简体中文。

### 7.3 保存校验

新增和修改分类时：

1. `icon` 为空，返回“请选择分类图标”。
2. `icon` 不在精选目录中，返回“请选择有效的分类图标”。
3. 校验通过后，原样保存名称，例如 `time`。

不修改 `wl_category.icon` 字段，也不新增 SQL 文件。

历史空值或失效值仍允许被查询，防止旧数据导致分类列表不可用；但再次保存该分类时必须重新选择有效图标。

## 8. 管理端设计

### 8.1 图标渲染依赖

`ruoyi-ui` 使用 Vue 2，因此增加并锁定：

```text
tdesign-icons-vue 0.4.2
```

该版本与当前小程序打包图标样式引用的 TDesign 图标版本一致。管理端使用 SVG 图标组件预览，不复制小程序的 WXSS。

### 8.2 组件边界

新增分类专用 `CategoryIconPicker` 组件，职责包括：

- 请求并缓存精选图标目录。
- 展示当前已选图标、中文名称和 `name`。
- 打开选择面板。
- 按中文名称、`name` 和关键词进行本地过滤。
- 点击选项后向父组件返回 `name`。
- 目录加载失败时显示中文错误和重新加载入口。

现有 `SimpleList` 不直接依赖 TDesign。为其增加按字段和列名称提供的通用作用域插槽：

- `field-icon`：分类页面注入 `CategoryIconPicker`。
- `column-icon`：分类页面注入图标预览。

没有使用这些插槽的其他页面继续走现有默认渲染逻辑。

### 8.3 选择交互

分类编辑框中的图标字段显示：

```text
[图标预览] 时间  time
```

点击后打开选择面板，面板包含搜索框和图标宫格。每个选项显示：

1. TDesign 图标预览。
2. 中文名称。
3. 图标 `name`。

选中项使用品牌色边框和勾选标识。选择后立即更新 `form.icon`，最终仍由现有分类保存操作提交。

分类列表的图标列显示图标预览和名称。遇到旧的空值或失效值时，显示 `file` 预览，并标记“图标配置已失效”。

## 9. 小程序设计

### 9.1 组件注册

在分类宫格组件的 `index.json` 中注册：

```json
{
  "component": true,
  "usingComponents": {
    "t-icon": "tdesign-miniprogram/icon/icon"
  }
}
```

### 9.2 分类宫格

将现有图片渲染：

```xml
<image class="grid__icon" src="{{item.iconUrl}}" mode="aspectFit" />
```

替换为：

```xml
<t-icon
  class="grid__icon"
  name="{{item.icon || 'file'}}"
  size="64rpx"
/>
```

公开分类接口继续返回 `icon`，不引入 `iconUrl`。空值使用 `file` 兜底；正常数据直接交给 TDesign 组件渲染。

## 10. 数据流

```text
后台请求精选图标目录
→ 管理员看到 <Icon name="time"> 的时钟预览
→ 点击“时间”
→ form.icon = "time"
→ 后端验证 time 在精选目录中
→ wl_category.icon 保存 "time"
→ 公开分类接口返回 icon: "time"
→ 小程序 <t-icon name="time"> 渲染时钟
```

## 11. 异常处理

1. **目录接口失败**：分类列表仍可查看；选择器显示加载失败和重新加载按钮，不退化为自由文本输入。
2. **历史空值**：管理端和小程序使用 `file` 预览；分类再次保存时要求重新选择。
3. **历史失效名称**：管理端显示原始名称和失效提示；小程序使用 `file` 兜底。
4. **非法提交**：后端返回“请选择有效的分类图标”，不写入数据库。
5. **依赖版本升级**：升级前先运行图标名称契约检查，任何精选名称缺失都阻止合并。

## 12. 验证要求

### 12.1 后端

- 图标目录返回固定顺序和完整字段。
- `time` 等精选名称通过校验。
- 空值返回“请选择分类图标”。
- 非精选名称返回“请选择有效的分类图标”。
- 图标目录接口要求 `library:category:list` 权限。
- 分类新增、修改仍保存普通字符串到现有 `icon` 字段。

### 12.2 管理端

- 图标选择器按目录遍历并渲染真实图标。
- 搜索支持中文名称、TDesign 名称和关键词。
- 点击 `time` 后表单值严格等于 `time`。
- 不提供自由文本输入。
- 分类表格能预览有效图标，并正确提示历史失效值。
- `SimpleList` 的其他页面保持原有表格和表单行为。

### 12.3 小程序

- 分类宫格注册并使用 `t-icon`。
- 图标来源为 `item.icon`，不再读取 `item.iconUrl`。
- `time` 显示时钟图标。
- 空值回退为 `file`。
- 自动检查首批 24 个精选名称均存在于当前小程序 `icon.wxss`。

## 13. 完成标准

管理员无需记忆 TDesign 名称即可看到并选择分类图标；选中时钟后数据库保存 `time`，公开接口返回 `time`，小程序显示对应时钟图标。后台、小程序和后端校验使用同一名称契约，且不改变数据库结构。
