# 人工积分调整业务编号自动生成设计

## 1. 背景

后台“微信用户”页面的“人工调整积分”弹窗目前要求管理员填写业务编号。业务编号实际用于积分流水幂等控制和审计追踪，不属于管理员需要理解或维护的业务数据，人工填写容易出现遗漏、重复和误用。

本次调整将人工积分调整的业务编号改为系统自动生成，并检查项目内其他业务编号使用点，确保管理表单不再要求人工填写业务编号。

## 2. 检查结论

项目内业务编号分为三类：

1. 人工输入：
   - 微信用户页面的人工积分调整弹窗。
2. 系统自动生成：
   - VIP 人工开通、续期和补偿。
   - 签到、分享、邀请、退款积分回收和文档解锁。
   - 小程序激励广告完成标识；该标识由小程序代码生成，不由用户填写。
3. 只读或查询用途：
   - 积分流水中的业务编号。
   - VIP 权益台账中的业务编号。
   - 后台积分流水查询条件。

本次只修改第一类。系统自动生成、只读展示和查询字段继续保留。

## 3. 目标

- 人工积分调整弹窗不再显示业务编号输入框。
- 管理员只需填写调整数量和调整原因。
- 前端生成隐藏批次标识，后端生成最终业务编号。
- 相同请求失败重试时保持幂等，不重复调整积分。
- 积分流水继续保存和展示最终业务编号。
- 不修改数据库表结构，不迁移或删除历史数据。

## 4. 请求契约

`PointAdjustmentRequest` 从：

```text
amount
bizNo
description
```

调整为：

```text
amount
batchNo
description
```

其中：

- `amount`：非 0 的积分调整数量。
- `batchNo`：前端生成的 20 位大小写字母或数字，页面不展示。
- `description`：必填的人工调整原因，去除首尾空白后最多 200 个字符。

旧的人工 `bizNo` 请求格式不再保留。

## 5. 前端交互

打开“人工调整积分”弹窗时：

1. 重置调整数量和原因。
2. 生成一次 20 位 `batchNo`。
3. 弹窗只展示调整数量和调整原因。
4. 提示语改为“扣减积分不能使余额小于 0，系统会自动记录本次操作编号。”

提交时发送：

```json
{
  "amount": -10,
  "batchNo": "20位字母数字标识",
  "description": "人工调整原因"
}
```

同一弹窗内提交失败后不重新生成批次标识。关闭弹窗并重新打开时生成新批次标识。提交期间确认按钮显示加载状态，防止重复点击。

## 6. 后端业务编号

后台根据批次标识和目标微信用户编号生成最终业务编号：

```text
MANUAL_POINT:<batchNo>:<userId>
```

示例：

```text
MANUAL_POINT:A1B2C3D4E5F6G7H8I9J0:7
```

该格式小于积分流水 `biz_no varchar(128)` 的长度限制。

## 7. 幂等和事务

人工积分调整继续使用现有的用户行锁、余额快照和业务编号唯一性检查：

1. 校验请求、用户编号和批次标识。
2. 根据自动业务编号查询已有积分流水。
3. 如果已有记录的用户、事件类型和调整数量一致，直接返回已有记录。
4. 如果业务编号已被其他操作使用，返回简体中文错误。
5. 加锁查询用户后再次检查业务编号，处理并发重试。
6. 计算调整后余额，扣减后不得小于 0。
7. 更新余额并写入包含前后余额快照的 `MANUAL` 积分流水。

整个过程继续在一个事务中执行。

## 8. 校验与错误

- 请求为空：`积分调整请求不能为空`
- 用户编号为空或小于等于 0：`微信用户编号不正确`
- 调整数为 0：`积分调整数量不能为0`
- 批次标识为空或格式不正确：`积分调整批次编号不正确`
- 调整原因为空：`积分调整原因不能为空`
- 调整原因超过 200 个字符：`积分调整原因不能超过200个字符`
- 余额不足：`积分余额不能小于0`
- 业务编号冲突：`积分调整业务编号已被其他操作使用`

所有接口注释、提示信息和错误响应使用简体中文。

## 9. 全项目人工输入防回归

新增管理端契约测试：

- 微信用户积分调整弹窗不存在业务编号表单项。
- 请求包含 `batchNo`，不包含人工 `bizNo`。
- 弹窗打开时生成批次标识。
- 提交失败时不替换现有批次标识。
- 提交按钮具有加载状态。
- 管理端其他业务编号列允许继续作为只读展示。

后端测试覆盖：

- 自动业务编号格式。
- 同批次同用户同调整数量的幂等重试。
- 同批次冲突。
- 非法批次标识。
- 空原因和超长原因。
- 扣减后余额不能小于 0。
- 并发加锁后的二次幂等检查。

## 10. 不在本次范围

- 不删除积分流水或 VIP 权益台账中的业务编号字段。
- 不修改小程序激励广告完成标识。
- 不修改签到、分享、邀请、退款和文档解锁的业务编号规则。
- 不新增数据库表或 SQL 迁移。
- 不迁移历史积分流水。
