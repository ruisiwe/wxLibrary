# 会员码生成套餐选择设计

## 目标

将后台“批量生成会员码”弹窗中的“套餐编号”数字输入框改为“会员套餐”下拉选择，避免管理员记忆或手工输入套餐编号。

## 数据来源

- 复用现有 `listVipPlans` 管理端接口，不新增后端接口。
- 每次打开生成弹窗时查询套餐，参数固定为：
  - `status: '0'`
  - `pageNum: 1`
  - `pageSize: 100`
- 下拉框只展示启用状态的会员套餐。

## 页面交互

- 字段标签由“套餐编号”改为“会员套餐”。
- 使用 Element UI `el-select` 和 `el-option`。
- 套餐加载期间显示下拉框加载状态。
- 下拉选项展示套餐名称、有效天数、价格和赠送积分，格式与微信用户详情页的会员开通弹窗保持一致。
- 打开弹窗时清空原套餐选择，不再默认使用套餐编号 `1`。
- 未选择套餐时点击生成，提示“请选择会员套餐”，不发送生成请求。
- 关闭并重新打开弹窗时重新加载启用套餐，避免继续使用过期列表。

## 提交与兼容性

- 生成请求仍提交原有 `planId` 字段。
- 生成数量、过期时间、明文会员码单次展示等现有行为保持不变。
- 不修改会员码后端接口、服务、数据表或权限。
- 不修改会员码记录表中的“套餐编号”列。

## 错误处理

- 套餐接口请求失败时沿用项目统一请求错误提示。
- 请求结束后关闭下拉加载状态。
- 没有可用套餐时下拉列表为空，管理员无法提交缺少 `planId` 的生成请求。

## 文件范围

- 修改 `ruoyi-ui/src/views/library/vip/code/index.vue`。
- 新增一个 `ruoyi-ui/tests` 下的会员码套餐选择契约测试。
- 保留工作区中其他已有未提交改动，不修改构建产物和环境配置文件。

## 验证

- 先运行新增契约测试，确认旧数字输入实现不能满足要求。
- 修改页面后复跑契约测试，验证：
  - 已移除套餐编号数字输入；
  - 已使用会员套餐下拉框；
  - 仅查询启用套餐；
  - 默认 `planId` 为空；
  - 未选择套餐时阻止生成；
  - 提交仍使用 `planId`。
- 运行 `git diff --check` 检查本次变更格式。
