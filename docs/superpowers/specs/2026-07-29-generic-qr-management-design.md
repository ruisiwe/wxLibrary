# 通用二维码管理与“我的”动态入口设计

## 目标

新增通用二维码管理能力。管理员可以在后台动态维护“加入社群”“关注视频号”等二维码配置；登录用户进入小程序“我的”页面后，系统遍历所有启用配置并自动展示多行入口。

同时将现有 VIP 客服微信二维码从私有 COS 改为本地文件存储。原 COS 图片不自动迁移，功能上线后由管理员重新上传。

## 用户体验

### “我的”页面

- 只有登录成功后才加载和展示二维码入口。
- 固定菜单“会员兑换”之后、“用户隐私协议”之前插入动态二维码区域。
- 请求 `wl_qr_config` 中未删除且状态为启用的数据，按 `sort_order`、`id` 排序。
- 每条配置显示一行菜单，名称来自后台配置，例如“加入社群”“关注视频号”。
- 点击任意一行进入同一个通用二维码页面，并携带配置编号。

### 通用二维码页面

- 根据配置编号读取当前启用配置。
- 显示配置名称、提示文字和二维码图片。
- 图片支持长按识别，并可点击预览。
- 配置存在但尚未上传图片时，显示“二维码暂未配置”。
- 配置被停用、删除或不存在时，显示“二维码配置不存在或已停用”。

## 后台二维码管理

新增独立菜单和页面“二维码管理”，遵循项目现有页面风格：

- 页面不使用最外侧卡片边框。
- 使用标准无边框表格、右侧刷新工具栏和分页。
- 列表显示名称、提示文字、图片状态、排序和启用状态。
- 支持新增、修改、上传、替换、清空图片、启停和删除。
- 新增配置时图片可以暂不上传。
- 配置编号由数据库生成，管理员不填写业务编码。
- 删除采用逻辑删除；数据库事务提交后清理对应本地文件。

后台权限：

- `library:qr:query`
- `library:qr:add`
- `library:qr:edit`
- `library:qr:remove`

## 数据模型

新建 `wl_qr_config`：

- `id`：主键。
- `menu_name`：在“我的”菜单和二维码页面显示的名称。
- `guide_text`：二维码页面提示文字。
- `image_path`：相对于二维码本地目录的安全文件名，不保存绝对路径。
- `sort_order`：显示顺序。
- `status`：`0` 启用，`1` 停用。
- 若依通用创建、更新和逻辑删除字段。

有效配置条件：

- `del_flag = '0'`
- `status = '0'`

不增加访问范围字段。小程序二维码配置和图片接口全部要求登录，因为动态菜单只属于登录后的“我的”页面。

## 本地文件存储

所有二维码图片以 `RuoYiConfig.getWechatProfile()` 为根目录：

- 通用二维码：`qr-config/<uuid>.<ext>`
- VIP 客服微信：`vip-customer-service/<uuid>.<ext>`

数据库字段只保存 `<uuid>.<ext>` 或受控相对子路径，不保存 `C:/...` 绝对路径。

文件要求：

- 支持 JPEG、PNG、WebP。
- 最大 2 MB。
- 校验声明类型、实际图片格式和可解码性。
- 文件名由服务端生成 UUID，客户端文件名不参与落盘路径。
- 每次读写前规范化并校验最终路径仍位于指定子目录内，拒绝目录穿越。

替换通用二维码或客服二维码时：

1. 校验并写入新文件。
2. 使用数据库当前旧路径作为并发更新条件。
3. 更新失败时删除新文件并保留旧配置。
4. 事务提交成功后删除旧文件。

清空或删除配置时，先更新数据库；事务提交成功后再删除旧文件。

## 接口边界

### 后台接口

- `GET /library/qr-config/list`：分页查询。
- `GET /library/qr-config/{id}`：查询详情。
- `POST /library/qr-config`：multipart 新增配置，可选图片。
- `PUT /library/qr-config`：multipart 修改配置，可选替换图片。
- `PUT /library/qr-config/{id}/clear-image`：清空图片。
- `PUT /library/qr-config/{id}/status/{status}`：启停。
- `DELETE /library/qr-config/{ids}`：逻辑删除。
- `GET /library/qr-config/{id}/image`：后台受保护图片读取。

接口使用简体中文注释、请求提示和错误信息。

### 小程序接口

- `GET /wx/qr-configs`：返回全部有效配置的轻量菜单数据。
- `GET /wx/qr-configs/{id}`：返回有效配置详情和图片可用状态。
- `GET /wx/qr-configs/{id}/image`：登录后读取二维码图片。

列表接口不返回图片内容。通用二维码页面使用带 `Wx-Token` 请求头的 `wx.downloadFile` 下载图片到临时路径，再交给 `<image>` 显示，避免把受保护图片地址暴露为匿名静态资源。

VIP 客服微信页面配置接口保持现有地址和字段；底层存储从 COS 对象键改为本地相对路径。其图片通过现有公开 VIP 页面能力读取，因为 VIP 页面配置当前就是公开接口；原数据库 COS 对象键在本地不存在时视为未配置，管理员重新上传后生成新的本地路径。

## 小程序文件边界

- “我的”页面加载会员资料时并行加载二维码菜单，二维码菜单失败不清空已加载用户资料。
- 在当前 `profile.wxml` 菜单内插入 `wx:for` 动态行，不覆盖已有昵称、菜单和样式改动。
- 新增通用二维码页面及服务，不为每种二维码新建页面。
- 在 `app.json` 注册通用二维码页面。
- 未登录直接进入通用页面时，由现有请求层的登录失效处理阻止读取。

## SQL 交付

按照项目规则在 `docs` 下新增 SQL 文件，包含：

- `wl_qr_config` 建表语句。
- “二维码管理”菜单。
- 查询、新增、修改、删除权限按钮。

不执行数据库迁移。实施完成后，在当前对话窗口完整粘贴同一份 SQL，供用户手工执行。

## 验证

- Mapper 契约验证有效配置过滤、排序、并发图片路径更新和逻辑删除。
- 本地存储测试覆盖格式、大小、随机文件名、目录穿越和安全删除。
- Service 测试覆盖新增、替换、清空、删除、启停以及失败补偿。
- Controller 测试覆盖后台权限、multipart 请求和小程序登录接口。
- 小程序测试覆盖动态多行菜单、排序结果、页面跳转、未配置图片提示和带令牌图片下载。
- 后台 Vue 测试覆盖标准表格风格、图片上传预览、清空和表单校验。
- VIP 客服微信测试更新为本地存储契约，确认原 COS 图片不自动迁移。
- 运行相关 Java 测试、小程序测试、后台前端测试和生产构建。

## 不在本次范围

- 不自动迁移原 COS 客服微信二维码。
- 不执行 SQL 或数据库迁移。
- 不为二维码增加匿名访问范围。
- 不改变头像、文档转换暂存等 `RuoYiConfig.getWechatProfile()` 下现有目录。
- 不发布、部署或推送代码。
