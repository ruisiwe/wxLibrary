# 新用户随机昵称与微信用户详情会员操作设计

## 目标

完成两个相互关联的微信用户体验改进：

1. 新微信用户首次登录时不再由前端提交或确认昵称，后台直接生成随机字母昵称。
2. 美化后台微信用户详情弹窗，展示真实头像和格式化时间，并允许管理员在详情内为用户开通或续期会员。

本次不改变微信用户与若依系统用户相互独立的身份边界。

## 新用户随机昵称

### 生成规则

新用户首次创建时，后台生成 10 位随机昵称：

- 字符集仅包含 `A-Z` 和 `a-z`；
- 使用 `SecureRandom` 生成；
- 不添加中文前缀、数字、符号或用户编号；
- 生成结果满足现有昵称最大长度和控制字符限制。

示例：`aBcdEFghIj`。

### 登录行为

`WxLoginService.createFirstUser` 不再读取首次登录请求中的昵称，始终调用后台随机昵称生成方法。

因此：

- 首次登录请求无需提交昵称；
- 即使旧版小程序仍提交昵称，后台也会忽略该值；
- 首次登录不再因为请求昵称包含 HTML 或控制字符而失败；
- 首次登录必须上传有效头像的现有规则保持不变；
- 已有用户再次登录时不会重新生成昵称；
- 已有用户通过资料修改接口主动修改昵称的功能及校验规则保持不变。

随机昵称只在成功创建新用户的路径生成。并发插入冲突后读取到的既有用户继续使用数据库中已经保存的昵称。

## 后台微信用户详情弹窗

### 顶部用户概览

现有“微信用户详情”弹窗调整为项目风格的用户资料卡：

- 左侧或顶部显示 80 像素左右的圆形头像；
- 显示用户昵称；
- 显示用户编号；
- 使用标签显示后台状态：启用或停用；
- 头像不存在或加载失败时显示 Element UI 默认用户图标。

头像地址复用现有受控读取接口：

```text
{VUE_APP_BASE_API}/wx/public/avatar/{avatarPath}
```

路径的每一段继续单独进行 URL 编码，不暴露服务器绝对目录。

### 详情字段

头像概览下方保留两列 `el-descriptions`，展示：

- 脱敏 OpenID；
- 积分余额；
- 会员状态；
- 会员到期时间；
- 最后登录时间。

不再显示原始头像路径文本。

时间统一通过若依现有 `parseTime` 格式化为：

```text
yyyy-MM-dd HH:mm:ss
```

空值显示 `-`；无会员到期时间显示 `未开通`。

### 会员状态

前端根据 `vipExpireTime` 与当前时间判断状态：

- 到期时间晚于当前时间：`VIP会员`，使用成功标签；
- 存在到期时间但已经到期：`已过期`，使用警告标签；
- 没有到期时间：`未开通`，使用信息标签。

详情弹窗的会员区域增加操作按钮：

- 未开通或已过期：显示“开通会员”；
- 当前有效会员：显示“续期会员”；
- 按钮继续使用 `library:vip:operation` 权限控制。

停用状态用户仍可查看详情，但不显示开通或续期按钮，避免为无法正常登录的用户新增会员权益。

## 开通或续期会员弹窗

### 弹窗内容

点击详情中的会员按钮后，在当前微信用户页面打开单用户会员操作弹窗。

弹窗显示：

- 当前用户头像、昵称和用户编号；
- 会员套餐选择框；
- 选中套餐的有效天数、赠送积分和价格；
- 操作原因输入框。

只加载状态为启用的会员套餐。

操作原因必填，最大长度沿用现有会员人工操作接口的 500 字符限制。

### 请求契约

不新增后端会员接口，复用现有：

```text
POST /library/vip-operation/open
```

请求内容：

```json
{
  "userIds": [7],
  "planId": 1,
  "batchNo": "20位字母数字批次标识",
  "reason": "后台用户详情人工开通"
}
```

其中：

- `userIds` 只包含当前详情用户；
- `batchNo` 在打开会员弹窗时生成一次；
- 请求失败后保留同一批次编号，保证重试幂等；
- 关闭并重新打开弹窗时生成新批次编号；
- 管理员不能查看或填写批次编号。

### 成功与失败

提交期间按钮进入 loading 状态，防止重复点击。

成功后：

- 关闭会员操作弹窗；
- 显示成功提示；
- 重新查询当前用户详情；
- 刷新微信用户列表，更新会员到期时间。

失败后：

- 保持会员操作弹窗和已填写内容；
- 保留原批次编号；
- 使用现有请求错误处理展示后端中文错误。

## 数据和接口影响

后台详情接口当前已经返回：

- `avatarPath`
- `vipExpireTime`
- `lastLoginTime`
- `nickname`
- `pointBalance`
- `status`

因此详情美化不需要修改后台详情 DTO 或新增接口。

随机昵称只修改微信登录服务。会员按钮只修改管理端页面并复用已有 VIP API。

不新增数据库表、字段、SQL 文件或数据迁移。

## 验收标准

- 新用户首次登录无须提交昵称，数据库中保存 10 位随机大小写字母昵称；
- 已有用户昵称不会因登录而被随机覆盖；
- 后台详情弹窗显示头像、清晰的会员状态和格式化时间；
- 管理员可以在详情内为启用用户开通或续期会员；
- 会员操作保持既有幂等、权限和业务逻辑；
- 相关后端测试、前端契约和生产构建通过；
- 任务提交不包含用户现有改动、环境配置或构建产物。
