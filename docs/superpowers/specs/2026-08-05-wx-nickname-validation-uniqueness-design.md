# 微信用户昵称校验与唯一性设计

## 目标

首次登录生成的随机昵称和用户主动修改的昵称均满足统一的格式、长度和全局唯一性要求。敏感字符白名单直接写在程序中，不新建敏感词表或其他数据库表。

## 昵称规则

昵称在校验前去除首尾空格，并遵循以下规则：

- 不能为空，也不能传入 `null`；
- 最长 20 个 Unicode 字符；
- 仅允许中文、英文字母、数字、下划线 `_` 和短横线 `-`；
- 完整昵称不能是 `null` 或 `undefined`，判断时忽略大小写；
- 昵称在全部微信用户记录中保持唯一，包括已逻辑删除的记录；
- 唯一性遵循数据库 `nickname` 列的排序规则，因此在默认不区分大小写的排序规则下，`User` 与 `user` 视为重复。

格式错误分别返回简体中文提示：昵称不能为空、昵称长度不能超过20个字符、昵称只能包含中文、英文字母、数字、下划线和短横线、昵称不能使用保留名称。重名统一返回“昵称已被使用，请更换后重试”。

## 后端设计

`WxLoginService` 负责昵称格式校验和可用性检查。Mapper 增加按昵称统计其他用户的查询，修改资料时排除当前用户编号；查询不排除逻辑删除记录，使程序预检与数据库唯一索引一致。

首次登录继续生成 10 位英文字母随机昵称。每次生成后先检查昵称是否已存在；插入时仍以数据库唯一索引作为并发兜底。如果插入发生昵称碰撞，重新生成并重试；如果冲突来自同一个 `openid` 的并发首次登录，则沿用当前并发登录恢复逻辑。重试次数必须有上限，超过上限时返回简体中文服务错误，不能无限循环。

已有用户通过登录请求携带昵称或通过 `/wx/profile` 修改昵称时，均先执行相同的格式与唯一性检查。数据库更新发生并发唯一键冲突时，将异常转换为“昵称已被使用，请更换后重试”，不向客户端暴露数据库错误。

## 数据库设计

不新建表。在初始化脚本中将 `wl_wx_user.nickname` 改为 `varchar(20)`，并增加 `uk_wx_user_nickname` 唯一索引。

按照项目约定，在 `docs` 下新增独立 SQL 文件，包含以下人工迁移内容：

1. 查询超过 20 个字符的历史昵称；
2. 查询按当前数据库排序规则重复的历史昵称；
3. 将昵称列修改为 `varchar(20)`；
4. 增加昵称唯一索引。

实施过程只创建 SQL 文件，不执行数据库迁移。若预检查询发现历史不合规数据，由人工先处理；变更 SQL 不自动改名或删除用户数据。

## 测试设计

后端测试覆盖以下行为：

- 接受中文、英文字母、数字、下划线和短横线；
- 拒绝空值、空白、超过 20 个字符、HTML/控制字符、空格、标点、表情符号；
- 拒绝大小写不同的 `null` 和 `undefined`；
- 修改为自己的原昵称不报重名；
- 修改为其他用户昵称时返回统一中文错误；
- 首次登录随机昵称查重，碰撞后重新生成；
- 并发唯一键冲突不会泄漏数据库异常；
- Mapper XML 包含昵称唯一性查询；
- 初始化 SQL 包含 `varchar(20)` 和 `uk_wx_user_nickname`。

验证使用 Java 8 和 IntelliJ 自带 Maven，运行昵称相关的聚焦测试，并在完成后运行 `ruoyi-wechat-library` 相关测试。现有未提交改动不纳入本功能提交。

## 非目标

- 不建立敏感词库或敏感词管理页面；
- 不允许管理员配置昵称白名单；
- 不执行发布、部署或数据库迁移；
- 不修改微信用户与若依 `sys_user` 相互独立的身份边界。
